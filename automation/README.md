# Googleフォームからの貸出・返却の自動反映セットアップ

スタッフが「本を借りる」「本を返す」のGoogleフォームに入力すると、自動でこのサイト
（`data/books.json`）に貸出・返却が記録され、GitHub Pagesへ公開されます。

本の指定は、サイトの各本のカードに表示されている **「No.◯」の番号** を使います
（タイトルの入力ミスで本が特定できなくなるのを防ぐため）。

## 全体の流れ

```
Googleフォーム回答（貸出 / 返却）
   → 連携するGoogleスプレッドシートに自動で行が追加される
   → スプレッドシートの Apps Script が「フォーム送信時」に自動起動
   → GitHub API 経由で data/books.json を更新
   → GitHub Pages が自動で再デプロイ
```

貸出用・返却用で、フォーム／スプレッドシート／Apps Scriptプロジェクトをそれぞれ
1つずつ、合計2組作ります。

## 1. GitHubのアクセストークンを発行する

1. GitHubで自分のアイコン → **Settings → Developer settings → Personal access tokens
   → Fine-grained tokens** を開く
2. **Generate new token**
   - Repository access: **Only select repositories** → `tanpopo-toshokan` を選択
   - Permissions → **Contents** を **Read and write** に設定
   - 有効期限はお好みで
3. 発行されたトークン（`github_pat_...`）をコピーしておく
   （**このページを閉じると二度と表示されません**。安全な場所に一時保存してください）

貸出用・返却用の両方で、同じトークンを使い回してかまいません。

## 2. 「本を借りる」フォームを作る

以下の質問を作成する（表記はこのままでOK）。

| 質問 | 種類 | 必須 |
|---|---|---|
| 本の番号 | 記述式 | ✅ |
| 借りた人の名前 | 記述式 | ✅ |

フォームの「回答」タブ → 緑色のスプレッドシートアイコン →
「新しいスプレッドシートを作成」で連携する。

連携したスプレッドシートを開く → メニューの **拡張機能 → Apps Script** を開き、
デフォルトの `Code.gs` の中身を全部消して、このリポジトリの
`automation/loan-form-to-github.gs` の中身を貼り付ける。

左側の歯車アイコン「プロジェクトの設定」→ 一番下「スクリプト プロパティ」で
以下を追加する（**コードには直接書かない**）。

| プロパティ | 値 |
|---|---|
| `GITHUB_TOKEN` | 手順1で発行したトークン |
| `REPO_OWNER` | `andominami` |
| `REPO_NAME` | `tanpopo-toshokan` |

上部の「時計」アイコン（トリガー）→ **トリガーを追加**
- 実行する関数: `onFormSubmit`
- イベントのソース: `スプレッドシートから`
- イベントの種類: `フォーム送信時`
- 保存時にGoogleアカウントの権限承認を求められるので許可する

## 3. 「本を返す」フォームを作る

同様に、以下の質問だけを持つ別のフォームを作る。

| 質問 | 種類 | 必須 |
|---|---|---|
| 本の番号 | 記述式 | ✅ |

こちらも新しいスプレッドシートに連携し、Apps Scriptには
`automation/return-form-to-github.gs` の中身を貼り付ける。
スクリプト プロパティ・トリガーの設定方法は手順2と同じ
（`GITHUB_TOKEN` / `REPO_OWNER` / `REPO_NAME` を登録し、`onFormSubmit` の
「フォーム送信時」トリガーを追加する）。

返却フォームは、その本が現在貸出中である最新の記録に返却日を入れます。
貸出中の記録がない番号を送信するとエラーになります（Apps Scriptの実行ログに残ります）。

## 4. テストする

実際に貸出フォーム・返却フォームからそれぞれ1件テスト投稿してみて、数分後に
https://andominami.github.io/tanpopo-toshokan/ に反映されているか確認する。

うまく反映されない場合は、Apps Scriptエディタの左側「実行数」から
エラーログを確認できます（GitHubトークンの権限不足、本の番号の間違い、
既に貸出中の本を再度貸し出そうとした、などがよくある原因です）。
